## 16. Root Cause

- **ROOT CAUSE**:
  The browser navigated to `http://localhost:3000/login` (the Next.js host development server), which was built using a hardcoded legacy LAN IP `NEXT_PUBLIC_API_URL=http://192.168.1.20:3001/api` in `frontend/.env.local`. When the user changed networks, the IP `192.168.1.20` became unreachable. The browser's login API fetch attempted to connect to `192.168.1.20:3001` and hung for 15 seconds until `apiFetch`'s `AbortController` timed out and rendered "Request timed out. Please try again." Meanwhile, the official hackathon stack is running inside Docker on port 80 (`http://localhost`) with relative `/api` paths, where authentication is fully functional.
- **WHY IT HAPPENS**:
  Next.js Turbopack inlined the compile-time value `"http://192.168.1.20:3001/api"` from `frontend/.env.local`. The browser sends TCP SYN packets to `192.168.1.20:3001`, which are dropped on the `192.168.0.0/24` subnet. After 15,000ms, the request aborts.
- **AFFECTED COMPONENT**:
  `frontend/.env.local` (and port confusion between dev server `:3000` and hackathon proxy `:80`).
- **WHY IT ONLY APPEARED NOW**:
  On the prior Wi-Fi network, the machine's assigned IP was `192.168.1.20`, allowing requests to resolve locally. Changing to a network on subnet `192.168.0.0/24` invalidated that IP.
- **WHY YOUTUBE/GENERAL INTERNET SPEED IS NOT RELEVANT**:
  External internet traffic uses WAN routing via the active gateway `192.168.0.1`. The login timeout was caused by an attempt to reach a private LAN address on an unreachable subnet.
- **SAFE FIX**:
  1. Updated `frontend/.env.local` to use `http://localhost:3001/api` (and `http://localhost:3001` for WS), matching standard configuration in `frontend/.env.example` and `design.md §133`.
  2. Cleaned stale `192.168.1.20` entries from `frontend/next.config.mjs` and `backend/.env`.
  3. Clearly documented that the verified hackathon application is accessed at **`http://localhost`** (port 80) or the Cloudflare HTTPS URL, **never** `http://localhost:3000`.
